Orbit — system and accessibility

The bet: students already think in places and times, not categories. A spatial commons makes the campus legible and makes commitments feel like tickets you hold. The risk is that spatial interfaces become keyboard-hostile and that a dark default fails outdoors — so both are addressed directly in this board rather than promised.

Type + layout

Sora

Display, 600. Public Sans for reading at 16px. IBM Plex Mono for times, codes and table heads.

  • Map is a 56px grid; nodes sit on it, labels stay horizontal.
  • Ticket uses a dashed perforation, not a shadow.
  • Console reverts to the same ruled tables as Kesho's desk.

Motion

  • Panels rise 10px and fade once, 500ms, 40ms stagger.
  • No drifting labels: motion is opacity and 10px rise only.
  • Theme switch cross-fades 300ms; instant under reduced motion.
  • Reduced motion removes all reveals and transitions; map and list still work.

Accessibility in this board

  • Every map node is a button with a full accessible name; reading order is club order.
  • Map/List switch uses aria-pressed and a real table alternative; without JS both are visible.
  • Daylight toggle works with the keyboard and sets aria-pressed, not just colour.
  • Status chips read "Member", "Open to join", "Waitlist" — colour is redundant.
  • Ticket code is text; the QR is decorative. Time elements carry real datetimes.
  • Contrast: text 17:1, mint 11.9:1, rose 9.7:1 at night; every daylight pair AA.
  • Focus ring 2px mint with 2px offset; 42–44px targets; tables have captions and scopes.

Honest risks

  • A map can imply distance accuracy it doesn't have — labels say "12 min walk", not metres.
  • Dark-first is a poor default outdoors; daylight is one tap away and remembered per session.
  • Tickets are charming but must still expose plain details for screen readers.
  • More chrome than Kesho; needs discipline to stay this quiet.
